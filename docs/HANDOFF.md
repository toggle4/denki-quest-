# HANDOFF — 引き継ぎ書（Claude Code 向け）

この文書は、claude.ai のチャットで決めた設計・データ・方針をすべてまとめたもの。
Claude Code はまずこの文書を読み、「現在のタスク」から作業を始めること。
チャット側は今後も教材データ（lessons / units）を作り続け、Claude Code はアプリ本体を担当する。

---

## 1. プロジェクトの目的

未経験者が中学理科の復習から始めて第二種電気工事士（筆記・技能）に合格するための iOS 学習ゲーム。
- 目安学習時間 200 時間。ただし期間の記述はアプリに入れない
- **基礎固め**と**網羅性**を最重視。計算問題は数値を変えて繰り返せる（テンプレート問題）
- 集中が途切れない設計：1セッション 5〜8 分、説明と問題を交互に、コンボ、ボス戦
- 品質が良ければ App Store 公開を検討。過去問や他人の画像は使わない（オリジナル問題・自作SVG）

## 2. 経緯（何が起きたか）

1. 以前、別の Claude Code セッションで第二種電気工事士の学習ゲーム（以下「旧ゲーム」）を作っていた。ユーザーはそのUI・構成を気に入っている。
2. その後 claude.ai のチャットで教材（基礎ステージのテキストと問題データ）と設計書を作った。
3. チャット側は旧ゲームの存在を知らず、「ゼロから作る」指示を出した。Claude Code が新しく DenkiQuest プロジェクトを作り、旧ゲームが見えなくなった（上書きの可能性）。
4. **ユーザーの希望：旧ゲームを復元し、そのUIを土台にして、チャットで作った教材データと設計を継ぎ合わせる。新規に作り直さない。**

## 4. 確定している設計（変更禁止。変えるときはユーザーに確認）

### 4.1 カリキュラム
- docs/curriculum.md のとおり。ステージ0（基礎12単元）→1（図記号・器具）→2（配線図）→3（施工・検査・法令）→4（配電理論・配線設計）→5（技能）
- ステージ0はF01〜F08（中学理科範囲）が作成済み。F09〜F12（交流・磁気・インピーダンス・三相）はチャット側で今後作成

### 4.2 説明と問題を混ぜる（最重要の設計変更）
- 「テキストを全部読んでから問題」ではない。**説明画面の直後に、いま読んだ概念の問題が1〜2問差し込まれる**
- 教材 Markdown の `<!-- quiz: id, … -->` が差し込み位置、`<!-- session-quiz: … -->` がセッション末のまとめ問題
- 詳細は content/lessons/README.md「画面の流れ」「戻る・進むのルール」

### 4.3 戻る・進むのルール
- 説明画面の間は自由に前後できる
- 問題画面に入ったら、前の説明画面には戻れない（戻るボタンなし）
- 問題を終えて次の説明に進んだら、直前の問題画面より前には戻れない
- 途中で閉じたら「最後に終えた問題画面の直後」から再開
- 既読セッションの読み直しは単元マップ経由で「復習モード」（説明のみ、問題なし）

### 4.4 問題データ
- content/schema.md のとおり。type は multipleChoice / numericInput / trueFalse / matching / imageChoice / **template**
- template は variables・constraints・answerFormula・distractors で数値をランダム生成。間隔反復の履歴はテンプレート単位
- 不正解 → 解説 → 同じ問題（template は数値を変えて）再出題。2回連続不正解なら正解を示して先へ
- 単元クリア：直近10問の正答率 90%以上（ステージ0は95%）＋ボス戦（`boss.pick` 問を `timeLimitSeconds` 内に連続正解）
- 間違えた問題は 1日→3日→7日→14日 後に再出題（SwiftData で管理）
- 弱点検知：同じ template で difficulty 2 以上を3回連続で間違えたら difficulty 1 に戻す

### 4.5 技術
- Swift / SwiftUI、iOS 17 以上、SwiftData、外部ライブラリ原則なし
- content/ はフォルダ参照で Bundle に入れる。教材ファイルの中身はアプリ側で書き換えない
- 図は Assets/figures/<名前>.svg。未作成のものは図名を書いたプレースホルダ表示
- xcodebuild でのビルド確認は `-destination 'generic/platform=iOS Simulator'` を使い、プロジェクトの署名設定（CODE_SIGN_*）は変更しない（過去に署名エラーの原因になった）

### 4.6 作業ルール
- 1回の依頼で1機能
- 変更後は必ずビルド確認してコミット
- 出題形式・Markdown 記法を追加したら schema.md / lessons/README.md も更新
- **既存の動くコードを作り直さない。拡張する**
